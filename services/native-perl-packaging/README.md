# Complete Perl Debian package candidate

Prepare the published Perl 5.44.0-2 recipe and its complete binary package family before replacing the old Perl runtime in Debian runner images. The separate original-publisher profile in #359 already executed its complete supported harness and retains its platform skips/TODO outcomes. That original-source proof does not establish this Debian recipe or its installed packages.

All four source-package inputs and all 41 published patches are hash-pinned. The hosted SDK installs the official Debian keyring and requires a valid OpenPGP source signature and strong checksums through normal dpkg-source options before extraction. No signature, dependency, interpreter, compiler, configure-regeneration or root check is disabled. Input signature verification is required but remains unproven until the hosted job succeeds. Candidate binary packages are unsigned review artifacts.

The SDK runs as UID 10001 in a disposable, network-disabled, read-only-root container with no capabilities and bounded memory, CPU, process and temporary storage. Normal dpkg-buildpackage binary construction builds the complete published family, including static/shared/debug flavours and documentation. The recipe's supported CC/CPP/LD variables select GCC 16.2; each generated flavour config must confirm that version. Python 3.15.1, normal build-dependency checks, compatibility level 13 and the unmodified packaging tests remain in place. No stage1/nocheck/nodoc profile or package subset is selected.

Debian's existing recipe changes five original test files and sets PERL_BUILD_PACKAGING. Those published adaptations are recorded separately from the untouched publisher proof. Source helpers may only finish with the exact publisher or hash-bound published-recipe contents; no additional assertion, test exclusion or source patch is authored. Full original-case/platform acceptance is never inferred from the normal package build. Complete build logs and visible skip/TODO/expected-failure markers are retained.

Retain all generated packages, control/file lists, build metadata, input/keyring/tool identities, actual compiler configs and source/helper hash receipts on failure. Presence of partial packages does not imply qualification. No package is installed on the operator, server or application images. Installed dependency/reverse-dependency, CLI/module and native ABI compatibility, original installed-package behavior and strict whole-image advisory qualification remain required before integration. The complete Perl SDK package family must not be confused with the minimal perl-base family observed in the currently inspected runtime images.

Sources: [Debian source pool](https://deb.debian.org/debian/pool/main/p/perl/), [normal dpkg-source signature/checksum gates](https://manpages.debian.org/trixie/dpkg-dev/dpkg-source.1.en.html), [publisher releases](https://www.cpan.org/src/).


The initial f15b623 job stopped at the required signature gate: stable debian-keyring 2025.07.26 carries an older certificate for primary fingerprint 76A28E42C9811D91E88FBA5E2EC0FFB3B7301B1F whose expiry was December 2025. A fifth pinned input now retrieves only that existing key's public certificate from Debian's official key service. Public-key armor is extracted from its HTML transport and its exact normalized bytes are SHA-256 bound. The worker verifies the full primary fingerprint against the original official SDK keyring, imports the old certificate followed by the renewal into a private SDK home so existing revocations remain, requires the merged key to be live, and supplies that public certificate through the normal per-user trustedkeys.gpg mechanism. The original dpkg-source signature/checksum gate then still has to pass under normal current-time, algorithm and revocation policy. No clock, expiry, signature or trust-model bypass is used, no different primary key is accepted, and operator/server trust stores are untouched. Cryptographic renewal acceptance remains pending hosted verification.
