# ACL source package candidate

Prepare ACL 2.4.0 from the published Debian 2.4.0-1 recipe with its normal compat-13 tooling. Publisher and Debian original source archives have the same SHA-256. Every source input is pinned, including Debian's two published patches: example LDLIBS linking and getfacl state handling. No upstream test file is patched.

The package-build phase uses GCC 16.2 / Python 3.15.1 as UID 10001 in a disposable, network-disabled, read-only-root SDK. It retains normal dependency checks, dpkg-buildpackage tests, all packages and corresponding source. Existing root-only cases skip in this non-root build phase; that phase does not qualify installed-package behavior.

A mandatory second SDK installs the exact hash-verified candidate library and CLI packages. Its case container has a read-only root, no network, an init process, unchanged process/resource bounds, and only CHOWN, DAC_OVERRIDE, FOWNER, FSETID, SETUID, SETGID and MKNOD capabilities needed for the original root/identity/file-permission fixtures. The original shopt fixture uses Bash through /bin/sh inside this SDK. Device-node use is limited to the private test tmpfs: safe null character device 1:3 and block 91:64 with read/create permission only; both host and container refuse the block fixture if major 91 is registered. No host device is mounted. Root is confined to this disposable candidate-test SDK; no operator, server or application-image package is installed.

Run all 16 original Linux cases through the unchanged upstream driver against the installed candidate commands. Verify every installed package file and every original case/helper hash. The four root-only cases must execute. The upstream Makemodule itself designates two NFS cases as expected failures; no new expected failure, exclusion or assertion is introduced. A qualified Linux case profile requires 14 PASS and exactly those two XFAIL, with zero skips, unexpected failures, errors or unexpected passes. The report never describes this as 16 passing cases or complete application/native security acceptance. Full NFS-server behavior is not established by an upstream expected failure.

Artifacts retain all original source inputs, complete built source, package controls/file lists, build and installed-case logs, process counts and SDK identities on failure. No nocheck/stage1 profile, dependency override or root-guard bypass is used. Strict application-image advisory checks are unchanged; package generation and this vendor-case profile do not clear an actual image finding or prove complete ABI/CLI/dependency equivalence.

ACL 2.4 adds a public API that collides with names in older GNU tar source builds. Debian bug 1141146 documents its tar source-build fix. Review that combination before application-image integration. Sources: https://download.savannah.nongnu.org/releases/acl/ ; https://deb.debian.org/debian/pool/main/a/acl/acl_2.4.0-1.dsc ; https://security-tracker.debian.org/tracker/CVE-2026-54369 ; https://bugs.debian.org/1141146 . Checksum identity is verified; detached PGP authentication is not claimed.
