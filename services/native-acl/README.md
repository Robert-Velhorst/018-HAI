# ACL source package candidate

Prepare ACL 2.4.0 from the published Debian 2.4.0-1 recipe with its normal compat-13 tooling. Publisher and Debian original source archives have the same SHA-256. Every source input is pinned, including Debian's two published patches: example LDLIBS linking and getfacl state handling. No upstream test file is patched.

The package-build phase uses GCC 16.2 / Python 3.15.1 as UID 10001 in a disposable, network-disabled, read-only-root SDK. It retains normal dependency checks, dpkg-buildpackage tests, all packages and corresponding source. Existing root-only cases skip in this non-root build phase; that phase does not qualify installed-package behavior.

A mandatory second SDK installs the exact hash-verified candidate library and CLI packages. Its case container has a read-only root, no network, an init process, unchanged process/resource bounds, and only CHOWN, DAC_OVERRIDE, FOWNER, FSETID, SETUID, SETGID and MKNOD capabilities needed for the original root/identity/file-permission fixtures. The original shopt fixture uses Bash through /bin/sh inside this SDK. Device-node use is limited to the private test tmpfs: safe null character device 1:3 and block 91:64 with read/create permission only; both host and container refuse the block fixture if major 91 is registered. No host device is mounted. Root is confined to this disposable candidate-test SDK; this qualification phase does not install a package on an operator or deployment server.

Run all 16 original Linux cases through the unchanged upstream driver against the installed candidate commands. Verify every installed package file and every original case/helper hash. The four root-only cases must execute. The upstream Makemodule itself designates two NFS cases as expected failures; no new expected failure, exclusion or assertion is introduced. A qualified Linux case profile requires 14 PASS and exactly those two XFAIL, with zero skips, unexpected failures, errors or unexpected passes. The report never describes this as 16 passing cases or complete application/native security acceptance. Full NFS-server behavior is not established by an upstream expected failure.

Artifacts retain all original source inputs, complete built source, package controls/file lists, build and installed-case logs, process counts and SDK identities on failure. No nocheck/stage1 profile, dependency override or root-guard bypass is used. Strict application-image advisory checks are unchanged; package generation and this vendor-case profile do not clear an actual image finding or prove complete ABI/CLI/dependency equivalence.

ACL 2.4 adds a public API that collides with names in older GNU tar source builds. Debian bug 1141146 documents its tar source-build fix. Review that combination before application-image integration. Sources: https://download.savannah.nongnu.org/releases/acl/ ; https://deb.debian.org/debian/pool/main/a/acl/acl_2.4.0-1.dsc ; https://security-tracker.debian.org/tracker/CVE-2026-54369 ; https://bugs.debian.org/1141146 . Checksum identity is verified; detached PGP authentication is not claimed.

## Qualified runtime image context

CI invokes this workflow once through `workflow_call` before its runner matrix. In addition to the unchanged installed vendor cases, the disposable SDK records libacl's baseline ELF class, machine, SONAME and exported symbol versions. The candidate must retain every baseline public symbol version and symbol type, plus every public OBJECT symbol size. This checks the exported surface, not complete behavioral ABI compatibility or every application path.

Only a successful installed profile (14 PASS, two original NFS XFAIL, zero SKIP or unexpected outcomes), matching original source/case/helper hashes, matching package and installed payload hashes, and preserved baseline exports can produce `runtime-candidate/`. The current-run artifact includes the exact libacl1 Debian package, its verifier and qualification manifest, with source inputs and full evidence retained alongside it. There is no cross-run/latest-artifact fallback.

Each of the 18 Debian runner images receives that directory as the read-only BuildKit named context `hai-native-acl`. Installation happens after its other apt/pip changes and before any configured final runtime user. The verifier checks Debian 13 and the qualified baseline package version, then checks the exact candidate package and installed regular payload files. The two Alpine runner images do not install Debian packages. Existing runner application code, contracts, dependency locks, interpreter pins and runtime users stay unchanged.

For a subsequent local image build, first download the artifact named `native-acl-fixed-package-candidate` from the successful reusable job of the exact reviewed CI run. Retain the source/evidence archive and check that run's commit and source qualification status. Extract the artifact so `runtime-candidate/` is under `.build/native-acl/`, or point `HAI_ACL_CANDIDATE_CONTEXT` at the absolute extracted `runtime-candidate` directory. Docker Compose then supplies that context to the affected image builds. Do not run the source SDK on an operator machine, install this package on the host, or substitute a package from an unrelated run. A missing or mismatched context fails the image build.

All 20 actual image inventories remain subject to the strict advisory gate, including modified findings. The Debian inventory must also report `libacl1` exactly `2.4.0-1`. Installing a fixed source candidate does not authorize a finding dismissal if the scanner continues to report it, or establish full native, NFS, runtime, server or deployment acceptance. This is a draft proposal; no deployment server is changed.


Python slim images exclude changelogs through their default dpkg path filters. The image-install command explicitly includes `/usr/share/doc/libacl1/*` for this one package, so every qualified regular payload file remains present and hash-verifiable. It does not relax the verifier, delete a package file or change the global dpkg configuration. Source 296d997's CrewAI image build exposed the missing changelog; that actual failure is retained as evidence. The SDK's original installed-case/symbol/export qualification passed independently of this runtime packaging issue.
